## Integrated design review

**Verdict:** ## Headline Verdict: SHIP-WORTHY ARCHITECTURE, FIX THE DOC-LEVEL CONTRACT COLLISIONS FIRST

This is a strong, unusually disciplined integrated design. The hexagonal cut is the right organizing axis for *this* system: the keystone (move #6) is localized into pure `domain/` files (`outcome_joiner.py`, `attribution.py`, `surfacer.py`), the three mandated swap seams are genuine ports each with a `Fake*` that is also the test seam, and the never-hallucinate + secret + approved-only invariants are made **structural** (frozen `__post_init__` that make an inconsistent `ScanVerdict`/`RecallResult`/`Episode` *unconstructable*, a single `_RECALL_PREDICATE` constant that kills the verified 6-site `tombstoned=0` predicate-scatter, index population sealed to one call site inside the status-flip tx). I verified the load-bearing reference claims against the actual tree and they hold: the `embedder.py:289-306` split-brain (random-head fallback + lazy PCA fit), the `service.py:184` surfacer cripple (`1.0+max(0.0,float(u))`, cannot demote), the `update_cas` rowcount CAS idiom, the `SqliteMeta` UPSERT kv, the gate's `evaluate(cands)` reading `c.alpha`, and `telemetry.py` carrying `trace_id` but no `task_ref`. The §7 prose-only-boundaries register (B1–B7) is exemplary — it names every soft boundary with the exact test + mutation that hardens it, which is precisely the agent-native "enforced contract over prose" discipline.

**Swap-seam cleanliness (9)** is the standout: each of the three axes swaps via one config key + one adapter file, with the core explicitly listed as untouched, and the D-IDX synthesis (Store-owns-and-drives-the-index, callers get NO mutation verb) is a *deeper* module than either pure alternative — it deletes both the external-DB-swap-is-a-refactor failure and the two-writer drift window in one move.

### The 3 things most likely to bite during the build

1. **The `UtilitySurfacer` is specified TWICE with incompatible signatures** (`order(scored, utility_of)` in 02-CONTRACTS §2.5 vs `rerank(query, cands)` in 05-BUILD-PLAN P0.4), and the ownership table lists it under both M04 and M08. The "single place to read before touching the system" and the "order is law" build plan hand an agent two different classes. This is the textbook Scattered-Truth flag, and because it sits on the Phase-2 credit path it will surface exactly when utility goes live.

2. **Family-at-query-time is an undefined seam.** Posteriors are `(episode_id, family_scope)`-keyed and `utility_map` demands a family, but recall takes only a query string and no doc says who derives the live query's family. The design honestly flags this (06 §5) but leaves it open — it is the one genuine residual Information-Leakage edge and it gates Phase 2.

3. **`docs/03-modules/` is empty** though it is referenced as the home of the per-module test contracts, and two "PORT AS-IS"/"PORT the math" claims (the gate's input shape; `ProjectionHead.to_bytes`) are actually reshapes/build-new that the prose under-states. None of these is an architecture defect — the resolutions exist elsewhere in the doc set — but they are exactly the kind of doc-truth drift that makes an agent build the wrong signature with full confidence.

**Bottom line:** the structure is buildable and the contracts mostly cannot lie. The risk is not the design — it is six doc-consistency closures (one of which, the surfacer collision, is load-bearing). Close those and an agent can execute this with essentially no further design reasoning.

**Top red flags:**
- Scattered Truth / contract collision: `UtilitySurfacer` declared with two incompatible public signatures across 02-CONTRACTS (`order(scored, utility_of)`) and 05-BUILD-PLAN (`rerank(query, cands)`), owned by both M04 and M08. An agent gets a different class depending on which 'authoritative' doc it reads first.
- Information Leakage (admitted-open): the query->family_scope mapping is undefined. Utility is keyed by family but recall has no family parameter and no specified deriver; the M04<->M08 seam is prose-gapped and blocks Phase 2.
- Stale/Prose contradiction: M04 says the entropy gate is 'PORT AS-IS, code unchanged' but the verified reference `gate_bundle.py:91 evaluate(cands)` reads `c.alpha` off candidate objects while the port is `evaluate(sims: list[float])` — the input shape and internals both change. (Contracts §7-B3 resolves it; the M04 prose still lies.)
- Missing artifact / dangling reference: `docs/03-modules/M01..M12` companion blocks are referenced as first-class deliverables but the directory is empty — an agent following the doc graph hits dead links for the per-module test contracts.
- Under-stated BUILD-NEW on a critical path: `ProjectionHead.to_bytes/from_bytes` is presented as a PORT but does not exist in the reference (codec is base64+JSON in migration.py and drops W_version); the frozen-head invariant that wins D-EMB depends on this new serialization round-tripping W_version, untested.
- Conscious-but-real ISP smell: the EpisodeStore god-port (15+ methods across episodes/blob/ledger/migration responsibilities). The design accepts this to keep the single-writer tx as one object and pre-segregates the method groups, but it remains the widest surface in the system and the one place a future ledger-extraction will force a multi-call-site edit.

**Must-fix before build:**
- RESOLVE THE UtilitySurfacer CONTRACT COLLISION (Scattered Truth, red-flags.md). Two authoritative docs disagree on the same class's public signature: docs/02-CONTRACTS.md §2.5 declares `UtilitySurfacer.order(scored: list[Scored], utility_of: Callable[[int], Optional[float]])` while docs/05-BUILD-PLAN.md P0.4 (lines 224-225) builds `UtilitySurfacer.rerank(query, cands)` with `__init__(utility_map, enabled, epsilon, rng)`. M04 and M08 interface blocks each independently 'own' a class named UtilitySurfacer with incompatible signatures, and the module-ownership table (CONTRACTS line 1028 vs 1024) lists it under BOTH. An agent told 'read 02-CONTRACTS first' (per 06-DESIGN-DOC §6 rule 1) will build `order()`; an agent following the build plan will build `rerank()`. Pick ONE signature, delete the other from every doc, and make exactly one module own the file `hive/domain/surfacer.py`.
- CLOSE THE family-at-query-time Information Leakage seam (the design's own admitted open flag, 06-DESIGN-DOC §5). Utility posteriors are keyed `(episode_id, family_scope)` and `UtilityStore.utility_map(family_scope)` requires a family argument, but the surfacer's recall-time entrypoint (`rerank(query, cands)` / `order(scored, utility_of)`) has no family parameter and no specified deriver of the *live query's* family_scope. Recall happens with a query string; credit is keyed by git-derived family. The M04<->M08 seam that maps a query to its family (who computes it, from what — repo cwd? agent_id? a config label?) is undefined. This is load-bearing for Phase 2 (utility cannot bias recall without it) and must be a typed seam, not prose, before P2.2.
- FIX THE M04 'PORT AS-IS' / gate-signature CONTRADICTION in the interface text. M04's interface block says the NormalizedEntropyGate is 'PORT AS-IS ... code unchanged', but the reference `gate_bundle.py:91` is `evaluate(self, cands: list)` reading `float(c.alpha)` softmax-mass off candidate objects (verified), whereas the M04/contract port is `evaluate(sims: list[float])`. The contracts doc §7-B3 correctly identifies and resolves this (re-shape to `list[float]`, add the named tests), but the M04 module prose still claims 'code unchanged', which is false and will mislead an agent porting the gate. Strike 'code unchanged' from M04; the input shape, the softmax internals, and the empty/[-1,1] behavior all change. This is a doc-consistency fix, not a design hole — the resolution already exists.
- WRITE THE docs/03-modules/M01..M12 companion blocks. They are referenced by 06-DESIGN-DOC §1/§5 and CONTRACTS line 9 as first-class deliverables holding each module's interface_block + test_contract, but the directory `docs/03-modules/` is EMPTY (verified). Per agent-native.md §6, a referenced-but-absent contract is a Prose-Only/Stale-Instruction risk: an agent following the doc graph hits dead links for the per-module test contracts. Either write them or delete the references and fold the per-module test contracts entirely into 02-CONTRACTS/05-BUILD-PLAN (which already carry most of them).
- PIN ProjectionHead.to_bytes/from_bytes AS BUILD-NEW with a W_version-survives-roundtrip test. 06-DESIGN-DOC §5 honestly flags that M01's 'PORT the ProjectionHead.pca math' claim is partly false: the reference (verified) has `ProjectionHead.random/.pca` but NO `to_bytes`/`from_bytes`; the only head codec is base64+JSON in `migration.py` and it DROPS W_version. Since the frozen-head-loaded-at-construction invariant (the whole D-EMB win) depends on serialize/deserialize round-tripping W_version, this serialization is new code on the critical geometry path and needs its byte layout + a `test_head_roundtrip_preserves_w_version` pinned before P1.2.
- STATE THE non_saturating + within_family_transfer ORACLES before Phase 2 (06-DESIGN-DOC §5). The §6.6 keystone (M10 `run_keystone_eval`) is the pre-committed KEEP/KILL gate for the entire move-#6 thesis, but `KeystoneResult.non_saturating` and `.within_family_transfer` have no stated computation. Per the TDD-first mandate these tests cannot be written test-first until the oracles are defined. This does not block Phase 1 (utility is OBSERVED-NOT-APPLIED) but is a hard gate for P2.1 and should be specified now while the design context is loaded.
